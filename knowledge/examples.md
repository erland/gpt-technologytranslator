# Exempel för Tekniköversättaren

## Exempel 1: API

# Kort förklaring

Ett API är ett kontrollerat sätt för två system att prata med varandra. Det gör att ett system kan be ett annat system om information eller be det utföra något, utan att behöva veta hur systemet fungerar inuti.

# Vad betyder det i praktiken?

Om en e-tjänst behöver hämta information från ett ärendehanteringssystem kan den göra det via ett API. Det gör kopplingen mer ordnad och lättare att förvalta än om systemen specialkopplas direkt mot varandra.

# Enkel liknelse

Ett API är ungefär som en meny på en restaurang. Du behöver inte veta hur köket fungerar. Du väljer något från menyn, skickar in en beställning och får tillbaka ett resultat.

# Varför spelar det roll?

API:er gör det lättare att återanvända information och bygga digitala tjänster. Samtidigt behöver de skyddas, dokumenteras och ägas över tid.

# Sammanfattning i en mening

Ett API är ett kontrollerat sätt för system att utbyta information och funktioner.

## Exempel 2: Molntjänst

# Kort förklaring

En molntjänst innebär att en organisation använder IT-resurser som levereras som en tjänst, istället för att själv äga och drifta all teknik. Det kan handla om lagring, system, servrar eller färdiga verksamhetsapplikationer.

# Vad betyder det i praktiken?

Organisationen kan ofta komma igång snabbare och skala upp eller ner lättare. Men man behöver också förstå ansvarsfördelning, informationssäkerhet, kostnadsstyrning och beroendet till leverantören.

# Enkel liknelse

Det liknar skillnaden mellan att äga en egen fastighet och att hyra en lokal med vissa tjänster inkluderade. Man slipper en del praktiskt ansvar, men blir också beroende av villkor, avtal och leverantör.

# Sammanfattning i en mening

Molntjänster kan ge flexibilitet och snabbare leverans, men kräver tydlig styrning av ansvar, kostnad och säkerhet.

## Exempel 3: Teknisk skuld

# Kort förklaring

Teknisk skuld betyder att tidigare tekniska genvägar eller gamla lösningar gör det svårare, långsammare eller dyrare att ändra systemet idag. Det är inte alltid ett misstag, men det behöver hanteras.

# Vad betyder det i praktiken?

Nya förändringar kan ta längre tid än väntat, enkla förbättringar kan bli dyra och risken för fel kan öka. Teknisk skuld kan därför påverka både budget, tidsplan och verksamhetens förmåga att utvecklas.

# Enkel liknelse

Det är som att skjuta upp underhåll i en byggnad. Det kan fungera ett tag, men till slut blir varje ny ombyggnad svårare eftersom grunden, elen eller rören behöver åtgärdas först.

# Sammanfattning i en mening

Teknisk skuld är gammalt tekniskt underhåll som till slut påverkar hur snabbt och säkert verksamheten kan förändras.
